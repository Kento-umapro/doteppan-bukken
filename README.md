# どてっぱん 出店物件情報サイト

GitHub Pages: https://kento-umapro.github.io/doteppan-bukken/

## データ構造（data.json）

```
{
  "generated": "YYYY-MM-DDTHH:MM",
  "prefs":   { "都道府県名": { "note": "...", "items": [ ... ] } },   // 標準物件
  "premium": { "都道府県名": { "note": "...", "items": [ ... ] } }    // 上級物件（1等立地）
}
```

`prefs` と `premium` の item は同じ形式（ll / sc / rk / pr / s / n / a / st / t / r / rs / tk / d / c / f / fn / tel / u / ad）。
トップページのタブで「標準物件」「上級物件（1等立地）」を切り替えて表示する。

## 掲載基準

共通: 23〜40坪・単一フロア・飲食店営業可（重飲食可が理想）・出店偏差値50以上のみ掲載
（偏差値は既存12店舗の実績と比較した出店評価。50＝既存店平均）

**東京都補正（2026-08-06導入）**: 東京都の物件は家賃水準が高く採算リスクが大きいため、
偏差値から一律 **-2.0pt** する（score-cli.js が自動適用。手動判定時も忘れずに適用すること）。

| 区分 | 坪単価（共益費・管理費込み） | 月額賃料 |
|---|---|---|
| 標準物件（prefs） | 8,000円〜20,000円 | — |
| 上級物件（premium） | 2万円超〜4万円 | **100万円以下** |

上級物件は、賃料が標準基準を超えていても立地の集客力により既存店平均以上の収益
（偏差値50以上）が見込めると判定された1等立地物件のみを掲載する特別枠。

### 掲載の精度基準（2026-08-20 月商＋倍率＋2km商圏基準・標準/上級 共通）
「月商300万を狙える都市商圏」に限定して厳選する。掲載は次を**すべて満たす**物件のみ:
- **20坪以上**（40坪以下）
- **出店偏差値 50以上**（既存店平均以上）
- **予測月商 300万円以上**（`prv`＝予測坪月商×坪数。予測坪月商＝85,060＋7.118×500m就業人口 なので**商圏人口が直接効く**）
- **予測倍率**：標準物件は **10倍以上**（家賃の10倍を売るのは最低条件）。**上級物件（1等立地）は 7倍以上**に緩和
  （坪単価が高く家賃が重いため倍率が構造的に伸びない特別枠）。いずれも**家賃＝賃料＋管理費（込み）**で算出
- **商圏 500m就業年齢人口 1000人以上**（坪ベースラインだけで通る低商圏＝人口ほぼ0の物件を除外）
- **2km圏 総人口 3万人以上**
- **2km圏 就業年齢人口 3万人以上**（＝「労働者数3万人以上」の代理。真の労働者数＝経済センサス
  従業者数メッシュは未取得のため、国勢調査の就業年齢人口20-69歳で代理している）

### 情報源（ネット／メール）と `src`
各物件は情報源を `src` で持ち、トップページで「すべて／🌐ネット情報／✉️メール情報」で切替表示する:
- `src:"net"` … ネット巡回（テンポスマート・テナントショップ）
- `src:"mail"` … 社内メール由来（**LeadLens/DataLens** の propertyLeads API。`tools/crawl/leadlens.py`）。
  LeadLensは緯度経度・可能業種(`allowedIndustries`)が構造化済みで、**重飲食可**の物件のみ取り込む。
  認証は Cognito アクセストークン（環境変数 `LEADLENS_TOKEN`・約1時間で失効・公開リポジトリに書かない）。
  ※恒久運用にはAPIキー（権限開放が必要）か自動ログインが要る。トークン未取得時はキャッシュを読む。

**既存どてっぱん店の除外**: 判定エンジンBASELINEの既存12店の住所と同一立地のリードは掲載しない
（`leadlens.py` が住所コアで照合）。

**メール物件の社内共有リンク**: メール物件はDataLensログインが必要な外部リンクの代わりに、各物件に
物件コード `cd`（displayCode）を持たせ、カードに「🔗 共有用ページ（社内）」= `#go=<県>|<cd>` を表示する。
このURLを開くと（monjaパスワード後）その物件へ直接ジャンプ・ハイライトする。DataLensアカウント不要。

**巡回・収集は従来どおり広く行う**（重点7府県＝大阪・京都・滋賀・愛知・群馬・埼玉・千葉を広めに、
全エリア20〜40坪で収集）。基準を外れた候補は削除せず、5km圏内は `hungree/extra.json`、
それ以外は `tools/crawl/held.json` に退避保全する（judge_add.js が自動適用）。

**滋賀（テナントショップ）の重飲食対応**: t-shop.co.jp の物件ページは重飲食可否を明記していない
（多くは「業種・用途は相談」）。もんじゃ・鉄板は排気・ガスの都合で**1階路面が現実的**なため、
滋賀は物件詳細の「所在階」を取得し**1階（路面）のみ掲載**する（2階・地下は held へ退避）。
掲載分も前業態は不明のため「重飲食は要確認」と注記する。

**トップページの県ボタン**は掲載0件の県を非表示にする（未巡回エリアの「該当なし」羅列を防ぐ）。


## 運用

- 毎朝の自動巡回は新着を `prefs` に「判定待ち」（sc なし）で追加し、掲載30日超を除外する。
  **上級基準（坪単価2万円超〜4万円・月額100万円以下）に該当する募集は `premium` に追加すること。**
- 判定作業で sc / rk / pr を付与し、偏差値50未満は削除する。

### 無人スコア判定（推奨・自動）

`tools/scoreing/score-cli.js` は、判定ツール画面の「🌐 Googleで自動取得」→「スコア判定」と
**同一のAPI・同一の計算式**で自動査定するCLI。計算エンジンは `index.html` から実行時に抽出する
ため、ツール本体を更新すればCLIも自動で追従する。

**判定待ちの一括処理は3ステップ（リポジトリのルートで実行）:**

```bash
# 1. 判定待ち(scなし)全件を抽出して入力JSONを生成
python3 tools/scoreing/make-pending.py
#    → tools/scoreing/pending.json の pop500(500m総人口・必須)・search・hire を
#      商圏の概算値で埋める(target2049 空欄時は pop500×44% で自動推定)

# 2. 自動判定(Google競合データ取得・東京都補正込み)
GOOGLE_API_KEY=<GoogleのAPIキー> node tools/scoreing/score-cli.js tools/scoreing/pending.json
#   (キーはルーチンの指示文など非公開の場所から渡す。リポジトリに書かないこと)
#   旧方式: DVS_URL=... DVS_TOKEN=... でも可(判定ツールサーバー経由)

# 3. 結果を data.json に反映(50以上=掲載・ll更新 / 50未満=削除+HUNGREE退避) + HUNGREE再生成
python3 tools/scoreing/apply-results.py tools/scoreing/pending.result.json
```

単発判定の入力例は `premium5.json` を参照。

**【正式手順】判定待ち物件（標準・上級とも）は必ずこのCLIで自動判定すること。**
巡回・判定セッションは判定待ちを追加したら、CLIで判定して sc/rk/pr を付与し、
50未満を削除してから data.json をプッシュする。手動のスコア判定ツール操作は不要。
（DVS_URL / DVS_TOKEN は判定ツールのデプロイ先とそのACCESS_TOKENを使用。リポジトリには書かないこと）

### 【予備】手動スコア判定の手順（CLIが使えない場合のみ）

1. 住所欄に物件の住所を入力したら、付加情報の**「半径100m以内の同業態競合数」の右にある「🌐 Googleで自動取得」ボタンを必ず先に押す**。
2. **3秒ほど待って競合数が入力欄に反映されたことを確認**する
   （周辺の同業態・飲食店データによる加点・減点がここで判定に入る）。
   見つからない場合は Google Maps で目視カウントして手動入力する。
3. 数値が入ってから「スコア判定」を押す。
4. これを**全物件**で実施する。自動取得（または目視カウント入力）を省略した判定は無効とし、やり直すこと。

## HUNGREE（スカイスクレイパー店舗5km圏サイト）

`/hungree/` はスカイスクレイパー社運営29店舗（ココイチ27・ラーメン大戦争2）の
**半径5km圏内**の募集物件を掲載する独立サイト。掲載条件は5km圏内のみ（坪数・賃料の制限なし）。

- `stores.json` — 店舗マスタ（座標付き）
- `crawl-areas.json` — 各店舗の5km圏がかかる市区町村リスト（巡回対象エリア）
- `found.json` — HUNGREE専用巡回の収集先。crawl-areasのエリアで見つけた飲食可貸店舗を
  どてっぱん基準に関係なく追加する（形式は親data.jsonのitemsと同じ・ll必須・URL重複排除・30日超は除去）
- `extra.json` — どてっぱん側で削除された5km圏内物件の退避先
- `build.py` — 親data.json + found + extra から data.json を再生成（巡回・判定後に毎回実行）
